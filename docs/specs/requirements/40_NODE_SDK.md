# Node SDK Requirements

## Contracts
- `REQ-NODE-001`: The trusted internal node-metadata layer shall include typed `PortSpec`, `PropertySpec`, and `NodeTypeSpec`. These records are registry and built-in implementation details and shall not be exported by the public `corex` function-plugin SDK. The unified workflow-interface contract is a separate planned scope under `REQ-NODE-036`; it does not widen this requirement or its existing proof.
- `REQ-NODE-002`: Executable registry entries shall be mutually exclusive private trusted-factory or Python-function entries. Public plugins shall declare a decorated function and return a mapping as defined by `REQ-NODE-050` and `REQ-NODE-051`; trusted built-ins that are not function-honest may retain private `spec()` / `execute(context)` factories. No public class-plugin contract shall remain.
- `REQ-NODE-003`: Node registry shall support registration, instantiation, and filtered discovery by normalized `category_path`, including descendant-inclusive prefix matching, path-backed `category_paths()` discovery, and derived display labels for presentation; display text is not a compatibility alias.

## Properties and Ports
- `REQ-NODE-004`: Node properties shall be declarative and editable from inspector. Workflow-interface defaults and publication semantics are a separate planned scope under `REQ-NODE-036`; they do not widen this requirement or its existing proof.
- `REQ-NODE-005`: Port exposure toggles shall be driven by node instance state and reflected immediately in UI. Workflow-level interface exposure is a separate planned scope under `REQ-NODE-036`; it does not widen this requirement or its existing proof.
- `REQ-NODE-006`: `PortKind` shall be `Literal["data", "flow"]`. Registry validation shall reject `exec`, `completed`, `failed`, and every alias or adapter for those retired control kinds; `flow` remains reserved for unrelated passive authoring surfaces.
- `REQ-NODE-038`: The trusted runtime contract shall define `DataPath = tuple[int, ...]`, `DataAccess = Literal["item", "list", "tree"]`, `DataTreeModifier = Literal["graft", "flatten", "simplify", "reverse", "clean"]`, and an immutable `DataTree` whose lexicographically sorted paths map to ordered item sequences. These types are not public `corex` exports. Public decorators select `structure="item"|"list"|"tree"`; only the internal `DataTree` represents tree topology, and ordinary Python lists and dictionaries remain Item values unless a List-structure output explicitly returns a non-string sequence.
- `REQ-NODE-039`: `PortSpec.data_access` shall default to `item`, remain author-declared rather than ordinarily user-editable, and describe structure separately from the element `data_type`. `ExecutionContext` shall expose `target_path`, `target_iteration`, and `iteration_count` while retaining `trigger`; `NodeResult.completed` shall be removed; and every output shall validate as exactly one Item value (including explicit `None`), a non-string List sequence, or a `DataTree` according to its declared access.
- `REQ-NODE-040`: Queue-safe runtime serialization shall define a recursive `data_tree` marker whose branch items may contain the existing artifact, array, tabular, worker-handle, and explicit-`None` runtime values without flattening or losing path order.
- `REQ-NODE-045`: The trusted metadata/runtime layer shall expose first-class ordered `Interval1D` values through `INTERVAL_1D_DATA_TYPE = "interval_1d"` and private `prop_interval_1d(...)`; the helper shall select `inline_editor="interval_slider"`, bounded finite metadata, and an author-selected increasing or decreasing direction without sorting endpoints. Public plugins shall use `corex.Interval` and `@corex.interval(...)`. Private `PropertySpec` shall also expose code-selected `searchable=True` only for static enum controls and `enabled_when=PropertyConditionSpec(...)` only for a same-node scalar value-IN condition. Private `SettingsGroupSpec` shall preserve declared group order, and same-key property-default inputs shall remain paired with their authored properties.
- `REQ-NODE-046`: The trusted internal SDK shall expose `DynamicPortGroupSpec` for node-owned dynamic port declarations. Each immutable registered declaration shall identify a stable group key and direction, its ordered backing-property key, capability limits, and immutable pure deterministic callbacks only for resolving the group's ordered ordinary `PortSpec` values from node properties, creating a new stable port key, and optionally validating or canonicalizing a proposed structural key rename. These callbacks shall not mutate the graph or backing properties. The same registered resolver output shall be authoritative for identical graph, UI, and runtime port projection. Group declarations and resolved `PortSpec` metadata are code-authored, not user-editable metadata, and no standalone reorder action is part of this contract. Public `corex` plugins shall not declare dynamic topology or factories.
- `REQ-NODE-048`: The built-in catalog shall register exactly `ssh_sftp.secret`, `ssh_sftp.host`, `ssh_sftp.run_command`, `ssh_sftp.run_script`, `ssh_sftp.upload`, and `ssh_sftp.download` under `Control > SSH/SFTP` as statically declared internal function entries normalized into ordinary trusted `NodeTypeSpec`, `PortSpec`, and `PropertySpec` metadata. Credential ports shall accept only `secret_data`, operation host ports shall accept only `ssh_sftp_host_data`, upload/download Sources shall use List access, and the Host value shall be a queue-safe tagged data descriptor containing endpoint and authentication configuration rather than a live client, transport, or session. The six built-ins shall use the shared registry, graph/Inspector projection, runtime snapshot, and generic function-adapter path without dynamic ports, node-specific QML, a parallel UI factory, or a connector service.
- `REQ-NODE-049`: `core.python_script` shall discover one synchronous `@corex.node` function named `run` through a bounded literal-only AST pass that never imports or executes user source. The allow-listed `input`, `output`, `text`, `number`, `switch`, `dropdown`, `slider`, `color`, `path`, `text_area`, `interval`, and `list` decorators shall resolve directly into ordinary ports, properties, and settings groups through one `NodeTypeSpec` instance resolver. The resolver shall reject unknown decorators, nonliteral decorator arguments, duplicate or reserved names, invalid types/structures, and invalid signatures with source locations; it shall not persist a copied manifest or add an alternate metadata path.

## Trusted Internal Metadata
- `REQ-NODE-007`: Private decorator helpers may author trusted built-ins without manually constructing `NodeTypeSpec`; those internal helpers use `category_path=` tuples. Authoring by external plugins shall not use that internal surface and shall use only packaged `corex` decorators with `@corex.node(category=(...))`; both forms normalize to the same category path, and derived display labels are presentation only. Private decorators and metadata constructors are not compatibility commitments.
- `REQ-NODE-008`: Statically declared Python functions and retained trusted factories shall normalize into the same validated registry metadata and presentation path. Public class-spec plugins shall not be supported.
- `REQ-NODE-016`: Private `NodeTypeSpec` shall expose `runtime_behavior` plus `surface_family` / `surface_variant` hints and additive `render_quality` metadata (`supported_quality_tiers`) so trusted built-ins can describe passive-vs-active behavior, including the active `media.panel` custom surface, host-routed canvas surfaces, and supported quality tiers declaratively with safe defaults when the field is omitted. These custom-surface and render-quality fields are not public `corex` decorators or exports.
- `REQ-NODE-017`: Trusted internal node metadata shall support `flow` port kinds and declarative editor hints such as multiline text and filesystem path pickers through the explicit surface/input contract. A property-backed custom surface may expose a distinct same-key optional data input without using the property as an execution default, as `media.panel.source` does. Public `corex.input` / `corex.output` declare data ports only, while public controls use the exact standard control decorators in `REQ-NODE-050`.
- `REQ-NODE-020`: passive flowchart SDK contracts shall publish exactly four stored ports keyed `top`, `right`, `bottom`, and `left`; those ports shall use `direction="neutral"`, `kind="flow"`, `data_type="flow"`, `allow_multiple_connections=True`, and a `side` value that matches the stored key, while non-flowchart specs keep the existing fixed-direction port contract. Flowchart variants that are library-icon-like rather than text-container-like shall keep their `title` label for catalog/search and may ship with an empty `body` default so graph rendering does not paint the library label inside the silhouette; the timestamp variant shall use a date placeholder body rather than the catalog label and shall expose a `live` boolean property for live timestamp rendering.
- `REQ-NODE-021`: node SDK and built-in catalog shall define `passive.annotation.group_backdrop` as a zero-port, collapsible, passive annotation node with `surface_family="group_backdrop"` and `surface_variant="group_backdrop"`, while sticky note, callout, and section header remain connectable note-style annotations instead of grouping items.
- `REQ-NODE-022`: execution-facing SDK contracts shall support `RuntimeArtifactRef` values plus `ExecutionContext.resolve_path_value()` and `ExecutionContext.runtime_artifact_ref()` helpers so node authors can emit or consume `saved://...` and `temp://...` project-file refs without reimplementing queue serialization or path resolution.
- `REQ-NODE-028`: Private `NodeTypeSpec.icon` remains the normalized metadata field, and public packages may supply it through the literal `@corex.node(icon=...)` field. The node-title icon contract shall treat it as a local image-path reference only: built-in relative paths resolve from the repo-managed node-title icon asset root, package-plugin relative paths resolve only from the validated generation asset root, and loose single-file plugins use the default icon. Supported suffixes are `.svg`, `.png`, `.jpg`, and `.jpeg` case-insensitive. Empty values, symbolic names, remote/data URLs, missing or unreadable files, unsupported suffixes, and paths outside the approved provenance root resolve to no title icon. Eligible repo-managed SVG title icons may derive live `icon_theme_aware=True`; plugin/package images remain authored and untinted. Passive flowchart library visuals derive from trusted `surface_family` / `surface_variant` metadata and remain outside public custom-surface authoring.
- `REQ-NODE-029`: the node SDK and built-in catalog shall define `io.folder_explorer` as a passive File I/O node with `surface_family="folder_explorer"`, `surface_variant="classic"`, a persisted `current_path` folder property using the filesystem path editor hint, a `current` path output for the selected/current folder, runtime exclusion from flattened execution graphs, and no persisted navigation/search/sort/selection/context-menu/maximized surface state.
- `REQ-NODE-030`: the node SDK and built-in catalog shall define `excalidraw.board` as the COREX-owned passive Excalidraw board node with `runtime_behavior="passive"`, `surface_family="web"`, `surface_variant="excalidraw_board"`, hidden JSON project properties `excalidraw_state` and optional `excalidraw_preview_ref`, imported-image refs under `excalidraw_state.files[*].artifact_ref`, no execution ports, and no arbitrary third-party web UI registration surface for external plugins outside explicit future surface/toolchain descriptors.
- `REQ-NODE-032`: The legacy public class SDK, plugin import aliases, class-probe and entry-point discovery, `ea_node_editor.plugins`, public descriptor/provenance barrels, and creation-wizard contracts shall remain removed without compatibility aliases. Public Python plugins shall enter only through the static `corex` declaration and schema-2 package paths in `REQ-NODE-050` and `REQ-INT-021`. Private `PluginDescriptor`, `PluginContractManifest`, `RuntimeBackendSpec`, `ToolchainSpec`, `ArtifactDescriptor`, and `SurfaceCapabilitySpec` records may remain for trusted built-ins and add-ons; they are not public authoring APIs. Remote endpoint trust and capability discovery are separate planned scopes under `REQ-INT-018` and `REQ-EXEC-020`; they do not widen this requirement or its existing proof.
- `REQ-NODE-033`: the node SDK and built-in catalog shall define `web.page_viewer` as a passive Web category node with `runtime_behavior="passive"`, `surface_family="web"`, `surface_variant="page_viewer"`, a safe persisted `start_location` browser configuration property, a `persist_browser_state` toggle plus optional hidden browser-state/preview properties so the surface reopens at the user's last visited location, passive execution behavior, and no scraper, DOM extraction, credential manager, browser automation, or multi-tab semantics.

Trusted metadata is not the public plugin interface. The public equivalent is:

```python
import corex

@corex.node(id="custom.scale.a7c31e9b", name="Scale", category=("Math",))
@corex.input("value", value_type=float, required=True)
@corex.output("scaled", value_type=float)
@corex.number("factor", default=2.0)
def scale(ctx, value, settings):
    return {"scaled": value * settings.factor}
```

The public `category` tuple accepts `1..10` non-empty trimmed string segments.
COREX derives display text with ` > `; the separator is not a source parser
contract and avoids ambiguity with single labels such as `Input / Output`.

- `REQ-NODE-035`: COREX shall register `engineering.cad_import`, `engineering.fe_import`, and `model.viewer` as built-ins. Import nodes accept an optional `path:path` input plus direct Browse property and emit `engineering_scene`. Model Viewer shall expose an ordered, addable scene-input group with at least one socket, stable identities, editable labels, and identical Scene/OCP Body/Geometry Group acceptance on every socket. Empty inputs are ignored, with at least one supplied scene required overall. It emits the existing viewer-session and structured-selection outputs. Per-scene opacity/color persist by scene ID; no old overlay port, settings, or conversion aliases remain.

## Planned Workflow and Solver Contracts
- `REQ-NODE-036`: The Node SDK shall define a planned unified workflow-interface contract for stable, typed, named inputs and outputs with direction, data access or passive-flow semantics, required or optional state, defaults, exposure, and compatibility; the same contract shall describe top-level, nested, published, linked, and headless workflows, and invalid or ambiguous interfaces shall fail validation instead of being inferred from presentation state. Acceptance of this contract is a prerequisite for permissioned agent orchestration under `REQ-ARCH-020` and `REQ-EXEC-022`. Evidence crosswalk: `SYN-OPP-0003`.
- `REQ-NODE-037`: The Node SDK shall define planned solver-neutral FEA process contracts for model preparation, materials, meshing, conditions, loads, solve, and result stages; stage inputs and outputs shall carry explicit type, units, coordinate-system, scoping, and provenance semantics while solver-specific extensions remain namespaced and capability-gated. This requirement shall not change the delivered `engineering.cad_import`, `engineering.fe_import`, or `model.viewer` contracts in `REQ-NODE-035`. Evidence crosswalk: `SYN-OPP-0007`.

## Public Function Plugin SDK

- `REQ-NODE-050`: The packaged top-level `corex` module shall expose exactly these 17 public names and no private metadata or runtime classes: `node`, `input`, `output`, `text`, `text_area`, `number`, `switch`, `dropdown`, `slider`, `color`, `path`, `interval`, `list`, `Any`, `Image`, `Color`, and `Interval`. Every public plugin and Python Script `@corex.input` and `@corex.output` shall require explicit `value_type=`; omission shall raise a source-located declaration error, and intentional broad ports shall use `value_type=corex.Any` without an implicit fallback or source rewrite. Bounded literal-only AST discovery shall never import or execute public source; it shall accept multiple uniquely named top-level sync/async node functions, same-module literal constants, exact decorator order/fields/types/structures, and the exact `ctx, <declared inputs>[, settings]` signature, while rejecting executable expressions, unknown decorators or fields, invalid/reserved/colliding names, unsupported signatures, and external claims on reserved built-in namespaces. Controls shall reuse the private normalized registry/presentation path; `settings` shall be immutable with defensive `to_dict()`, `port=True` overrides shall use presence rather than truthiness, functions shall return only declared string-keyed mappings with omitted outputs settling EMPTY and explicit `None` remaining a value, and `ctx.warn` shall emit bounded ordered structured warnings. `NodePlugin`, `PluginDescriptor`, `NodeTypeSpec`, `PortSpec`, `PropertySpec`, dynamic topology, factories, registry entries, private decorators, and backend-manifest types shall not be public SDK. The exact 76-function and 53-trusted-exception boundary is recorded in [COREX Novice Plugin SDK Migration Inventory](COREX_NOVICE_PLUGIN_SDK_MIGRATION_INVENTORY.md). Authoring and migration are documented in the [Novice Plugin Authoring Guide](../../PLUGIN_AUTHORING_GUIDE.md) and [Legacy Plugin Migration Guide](../../PLUGIN_MIGRATION_GUIDE.md), with runnable [Signal Plot](../../examples/signal_plot_function_plugin.py) and [strain conditioner](../../examples/strain_conditioner_plugin.py) source examples.
  `@corex.output` shall additionally accept the literal `type_from_input` name, defaulting to an empty string and mapping to internal `PortSpec.type_from_input`. A nonempty relationship shall reference an Any data input in the same node from an Any data output with matching access structure. Static and resolved/dynamic validation shall reject missing references, wrong directions, typed ports, mismatched structure, and flow relationships. Panel, Trigger, and every Stream Gate output shall opt in explicitly; Stream Gate shall reference Stream, never Gate. This metadata is a type-preservation promise, not runtime execution, function-body analysis, or value inference.
