# Persistence Requirements

## File Format
- `REQ-PERSIST-001`: Canonical project format shall be `.cxproj` version 5 (versioned JSON).
- `REQ-PERSIST-002`: Document shall include schema version, project metadata, workspaces, views, nodes, and edges.
- `REQ-PERSIST-003`: Serialization shall be deterministic (stable ordering) for diffability.

## Current Schema Normalization
- `REQ-PERSIST-004`: The coordinated format cutover shall use `.cxproj` v5, graph fragments v2, `.cxwf` v2, global custom-workflow store v2, and app preferences v8. The supported migration inputs are `.cxproj` v4, fragment/workflow/store v1, and the existing staged app-preference migration chain through v7; unknown envelopes remain unsupported without compatibility shims.
- `REQ-PERSIST-005`: One migration pass shall delete known control edges, `core.start`, `core.end`, `core.branch`, `core.on_failure`, `hpc.on_status`, control-kind subnode pins, shell mappings, stale exposed/locked/label metadata, and control-row state. It shall migrate nested fragments and workflows in the same pass, remove and report workflows left empty, default surviving edges to enabled with `input_order` from serialized order, and default surviving data ports to Item access with no modifiers or Principal.

## Session Persistence
- `REQ-PERSIST-006`: Last session shall persist workspace/view state across restarts.
- `REQ-PERSIST-007`: Metadata schema shall persist normalized UI state and workflow settings (`metadata.ui`, `metadata.workflow_settings`) for current-schema documents.
- `REQ-PERSIST-009`: Project, fragment, subnode, copy/paste, duplication, and workflow codecs shall persist edge `enabled` and `input_order`, sparse per-port modifier state, one mutually exclusive `principal_input_port_id`, dynamic subnode-pin access declarations, and the ordered node properties that back `REQ-NODE-046` dynamic port groups so stable resolved port keys retain their per-port state. The existing schema shall carry these ordinary node properties without a schema-version bump; resolver callbacks and resolved `PortSpec` metadata shall not serialize. The codecs shall not persist control-row expansion, runtime DataTrees, previews, caches, Trigger publications, or live workspace Auto/Manual state. Linked instances and durable snapshots remain separate planned scopes under `REQ-PERSIST-025` and `REQ-PERSIST-026`.
- `REQ-PERSIST-010`: Custom workflow snapshot interchange shall use `.cxwf` v2 for exactly one normalized definition; graph fragments and the global custom-workflow store shall use their v2 schemas. Nested definitions shall preserve ordered/enabled edges, access declarations, modifiers, and Principal consistently with project documents. Linked-instance identity remains a separate planned scope under `REQ-PERSIST-025`.
- `REQ-PERSIST-011`: App-wide graphics and authoring preferences, including passive node library display mode, shell-theme, graph-theme state, and Media Panel creation defaults, shall persist in the app-preferences v8 JSON document under `user_data_dir()` and remain separate from `.cxproj` and `last_session.json`. Version 8 shall preserve prior solution-mode behavior, migrate the existing media appearance values into `graphics.media_panel`, add default-on `source_input_exposed`, preserve unrelated settings, and migrate/write once through the normal preference store; live workspace Manual/Pause state shall not persist.
- `REQ-PERSIST-012`: graph-theme state shall be stored only under `graphics.graph_theme = {follow_shell_theme, selected_theme_id, custom_themes}` with custom graph themes serialized inline in app preferences rather than external files; custom node tokens shall be passive defaults only. Schema-5 project, fragment, and paste normalization shall preserve `visual_style` for passive and unresolved node types but drop it for known active and `compile_only` types, saves and scene payloads shall omit known non-passive `visual_style`, and no schema bump or compatibility shim shall be added.
- `REQ-PERSIST-013`: `.cxproj` project documents shall persist passive-node visual metadata, authored `media.panel` properties and Source exposure, `flow` edge labels/styles, and project-local passive style preset libraries under normalized project metadata. The three pre-cutover media node identities are unsupported and shall be rejected as unknown types; no alias, migration, or property fallback shall be added for them.
- `REQ-PERSIST-014`: `.cxproj` project documents shall persist authored Group title/collapsed state and geometry through the normal node document path, but shall not persist a body/rich-text property or derived membership/containment metadata; load shall recompute ownership from geometry. The old external type has no compatibility path, while tracked project fixtures are rewritten to `passive.annotation.group_backdrop`.
- `REQ-PERSIST-015`: `.cxproj` shall remain the canonical saved project file while project files live in a sibling `<project-stem>.data/workspaces/<workspace-folder>/nodes/<node-folder>/` tree containing node-owned `in/`, `out/`, and `tmp/` folders. Durable solution snapshot storage is a separate planned use of project-managed data under `REQ-PERSIST-026`; it does not widen this requirement or its existing proof.
- `REQ-PERSIST-016`: project-file state shall remain additive under `metadata.artifact_store`, with saved/temporary entry maps and optional temporary-root hints; saved refs persist as `saved://<artifact_id>` strings and temporary refs as `temp://<artifact_id>` strings inside ordinary project/node fields. Durable snapshot manifests and result artifacts are a separate planned contract under `REQ-PERSIST-026`; they do not widen this requirement or its existing proof.
- `REQ-PERSIST-017`: Imports and stored outputs shall write to node `tmp/` first. Save shall stage only referenced temporary and saved artifacts copy-on-write, rewrite candidate refs without mutating live state, and atomically replace only the currently bound `.cxproj`. Immutable sidecar targets shall never be overwritten. The live document/artifact/runtime binding shall change only after committed reopen, integrity verification, and adoption; bounded orphan cleanup shall run afterward.
- `REQ-PERSIST-018`: First Save and distinct Save As shall publish a self-contained new `.cxproj` plus sibling `.data` tree with atomic create-new/no-clobber semantics. They shall carry referenced saved and temporary artifacts without a copy-mode choice, preserve source content and live binding through failure, and adopt the destination only after committed reopen and complete artifact/image/solution verification.
- `REQ-PERSIST-019`: autosave/session recovery may preserve temporary metadata and offer crash-only tmp recovery, while clean close without save discards temporary tmp data and its autosave snapshot.
- `REQ-PERSIST-020`: cross-process viewer authored state shall persist only stable node properties, cached summary or proxy metadata, and result/model path selections in `.cxproj`; session-scoped transport bundles, bundle roots, transport revisions, live-ready state, runtime handle IDs, worker viewer-session caches, and source-model fixtures remain runtime or test inputs rather than serialized project artifacts.
- `REQ-PERSIST-021`: `.cxproj` project documents, fragments, workspace snapshots, and duplication shall persist active-node default values only through the existing `NodeInstance.properties` field and shall retain view-local `hide_optional_ports`. Active-node `locked_ports` and `hide_locked_ports` shall not be written, restored, or copied; obsolete keys accepted by existing extra-field tolerance shall be dropped on the next write without a schema bump, compatibility alias, or replacement state map. Unavailable add-on placeholder metadata and passive-object `locked` persistence remain unchanged.
- `REQ-PERSIST-022`: title-icon persistence boundaries shall stay explicit: derived live `icon_source` and `icon_theme_aware` values shall not serialize into `.cxproj` project files, while `graphics.typography.graph_node_icon_pixel_size_override` persists only in the app-preferences document as a nullable app-global integer whose `null` mode follows `graph_label_pixel_size` and whose non-null values clamp to `8..50`.
- `REQ-PERSIST-023`: app preferences and restore paths shall persist add-on enabled-state plus pending-restart intent by add-on id, and `.cxproj` documents shall retain enough unavailable-session node metadata to reopen missing add-on nodes as locked unavailable-add-on projections and rebind them when the add-on returns without widening projection payloads into editable live schema.
- `REQ-PERSIST-024`: Excalidraw board persistence shall stay project-local and semantic: `.cxproj` documents persist drawing JSON only in the hidden node property `excalidraw_state`, persist imported image refs only as `excalidraw_state.files[*].artifact_ref`, persist preview references only as optional `excalidraw_preview_ref` artifact references, keep binary image imports in the owning node `in/` folder and previews in `out/` through the project artifact store, promote/rewrite referenced temporary refs during save and Save As, and shall not serialize `data:image` or base64 payloads, WebEngine availability, WebChannel runtime objects, fullscreen overlay state, or arbitrary third-party web UI registrations.
- `REQ-PERSIST-027`: A successful legacy cutover shall produce one sorted migration report, mark the in-memory project dirty, and never overwrite the source until Save. A legacy file with unresolved add-ons shall be rejected rather than partially migrated or wrapped in recovery machinery.
- `REQ-PERSIST-028`: `Interval1D` property values shall round-trip only through the existing recursive tagged runtime-value serializer, preserving increasing, decreasing, and equal endpoint order without a `.cxproj` schema bump. Slider bounds, step, direction, searchability, and conditions remain registry metadata; `expanded_settings_group_ids` remains the sole persisted settings-group UI state. Upstream `display_value` and related presentation facts remain transient and shall never replace the authored property value in documents or undo history.
- `REQ-PERSIST-029`: A stored secret shall persist only as the ordinary JSON envelope `corex.protected_secret.v1` with provider `windows_dpapi`, canonical `CurrentUser` or `LocalMachine` scope, and base64 ciphertext. Project documents, fragments, duplication, workspace snapshots, and undo history shall never store the plaintext; QML-facing payloads shall carry only `{has_value, scope}`. Worker transport shall preserve validated `secret_data` and `ssh_sftp_host_data` tagged mappings through the existing recursive runtime-value serializer without treating either as a live handle, and non-Windows secret operations shall fail closed without discarding an already stored envelope.
- `REQ-PERSIST-030`: Python Script shall persist its applied source and declaration-authored setting values as ordinary node properties in the existing project schema. Project, fragment, copy/duplicate, and history paths shall retain compatible values and normalized settings-group expansion IDs, while decorator manifests, resolved `NodeTypeSpec` metadata, and runtime-only values shall not serialize.

## Planned Persistence Contracts
- `REQ-PERSIST-025`: Project persistence shall support planned linked workflow instances as explicit references to an eligible workflow definition, its origin and expected revision, the unified interface binding, and local divergence state; load and resolution shall be deterministic, unavailable or incompatible definitions shall remain explicit without silent snapshot substitution, and detaching a link shall create an independent normalized snapshot while preserving provenance. Evidence crosswalk: `SYN-OPP-0001`.
- `REQ-PERSIST-026`: Project persistence shall store immutable solution record identity, manifests, result payloads, and integrity facts in project-managed data rather than inline project payloads. Each durable record shall bind the normalized workflow and interface revision, dependency and input provenance, implementation and toolchain versions, execution policy, and result integrity. Mutable freshness, invalidation, and disposition facts shall be reconstructed against the current graph, registry, and runtime and shall never be persisted as durable truth. Writes shall be atomic and portable, while credentials, live runtime handles, and session-only caches shall never become durable snapshot content. Acceptance of this contract is a prerequisite for permissioned agent orchestration under `REQ-ARCH-020` and `REQ-EXEC-022`. Evidence crosswalk: `SYN-OPP-0002`.
- `REQ-PERSIST-031`: Public plugin source paths or bytes, digests, package manifests, bundle/generation references, callable identities, and private registry entry records shall remain app/runtime-owned and shall never enter `.cxproj`, graph fragments, `.cxwf`, clipboard payloads, or project-session documents. Projects shall persist only existing node type IDs and semantic port/property values, preserving `.cxproj`, fragment, duplication, and copied Custom Workflow behavior across function conversion without a schema bump. Compatible additive metadata reloads shall leave authored values and incident wires unchanged; removals, direction/type/access/requiredness/property-type changes, or saved-value invalidation shall refuse before any package file, graph, registry consumer, runtime client, viewer, cache, or service mutation. This exclusion does not change `REQ-PERSIST-030`: the applied source of the separate `core.python_script` workflow node remains an ordinary persisted node property.

## Module Decomposition
- `REQ-PERSIST-008`: Persistence internals shall be split into project codec (`ProjectData` <-> JSON document), current-schema validation/normalization, and session/autosave storage service.
