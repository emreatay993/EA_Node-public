# UI/UX Requirements

## Layout
- `REQ-UI-001`: Main shell shall be rendered in QML as a client of the Corex kernel and include menu bar, top toolbar, left node library, center graph canvas, right inspector, bottom workspace tabs, and bottom console/log with Output, Errors, and Warnings severity badge tabs.
- `REQ-UI-002`: Workspace tabs shall support create, rename, duplicate, close, reorder, and switch.
- `REQ-UI-003`: Workspace tabs shall be displayed below the canvas area.
- `REQ-UI-004`: Each workspace shall support multiple named views (`V1`, `V2`, ...).
- `REQ-UI-005`: Each view shall preserve independent pan/zoom state.

## Node Library
- `REQ-UI-006`: Node library shall support text search and filtering by normalized category path, port direction, and data type; category filters shall be descendant-inclusive for path prefixes, nested category rows shall remain on the existing flat `ListView` surface with `category_key` collapse state, passive node rows shall honor the app-wide `text` / `icon` / `text_icon` library display setting by projecting flowchart passives as shape tiles only in icon mode, and the rendered ` > ` delimiter shall stay display-only so labels such as `Input / Output` remain single unambiguous category segments.
- `REQ-UI-007`: Double-click or button action shall add the selected node directly to the canvas through ordinary registry and graph validation, including `core.python_script`, without a creation wizard or generated-plugin side effect.

## Node Inspector
- `REQ-UI-008`: Selecting a node shall show editable properties and exposed-port toggles.
- `REQ-UI-009`: Collapse/expand control shall be available per collapsible node.

## Error UX
- `REQ-UI-010`: On execution failure, app shall switch to containing workspace, center failed node, and show error details.

## RC2 UX Surfaces
- `REQ-UI-011`: Application QML-shell client styling shall match Stitch references using QML theme tokens and surface hierarchy.
- `REQ-UI-012`: `ShellWindow` shall expose `show_workflow_settings_dialog()` and persist workflow settings metadata from a modal UI.
- `REQ-UI-013`: `ShellWindow` shall expose `set_script_editor_panel_visible()` and provide one shared Python script editor surface bound to the selected `core.python_script` node. The editor shall keep a dirty draft until Apply; Apply shall validate and commit the decorator-defined script plus its resolved ports and properties. Explicit Run or Run Selected shall first consume a valid pending Apply for that selected script and shall block dispatch without partial model mutation when validation fails. Node creation shall not open an editor wizard.

## Subnode UX Surfaces
- `REQ-UI-014`: Shell and canvas UX shall support subnode scope navigation (breadcrumbs + keyboard navigation), group/ungroup transforms, and subnode pin editing directly from the inspector/library workflows. Unified workflow-interface authoring is a separate planned scope under `REQ-NODE-036` and `REQ-UI-053`; it does not widen this requirement or its existing proof.
- `REQ-UI-015`: File menu UX shall provide project-local custom workflow interchange through versioned `.cxwf` import/export actions that remain separate from `.cxpkg` node package actions.

## Graphics Settings UX Surfaces
- `REQ-UI-016`: `ShellWindow` shall expose `show_graphics_settings_dialog()` and the Settings menu shall provide an app-wide Graphics Settings modal covering grid, minimap, snap-to-grid default, passive node library display (`text` / `icon` / `text_icon`), shell-theme selection, graph-theme follow-shell or explicit selection, and graph-theme manager access.
- `REQ-UI-017`: shell and graph canvas chrome surfaces shall support live application of shared shell-theme tokens for `stitch_dark` and `stitch_light`.
- `REQ-UI-018`: passive-node and edge visuals shall resolve through dedicated graph-theme tokens while active and `compile_only` node body, outline, title, port-label, inline-control, and selection colors use fixed semantic palettes selected only by shell brightness; canvas chrome (background, grid, minimap, marquee, and drop-preview) stays on the shell-theme path.
- `REQ-UI-019`: `ShellWindow` shall expose `show_graph_theme_editor_dialog()` and provide a graph-theme manager/editor that groups built-in read-only themes and editable custom themes with create, duplicate, rename, delete, use-selected, and token-editing workflows; node-color controls shall be presented as `Passive Node Defaults` and shall not override active or `compile_only` node chrome.

## Passive Visual Authoring UX Surfaces
- `REQ-UI-020`: graph canvas node rendering shall route through a host/factory surface split that keeps the standard node contract stable while loading passive `flowchart`, `planning`, `annotation`, and `group_backdrop` families plus the active `media` family by `surface_family` / `surface_variant`, and shall reuse the shared header inline title editor across standard, passive, active custom-surface, collapsed, and scope-capable node shells instead of adding per-surface title workflows.
- `REQ-UI-021`: passive nodes and `flow` edges shall expose style edit/reset/copy/paste workflows plus project-local preset CRUD from the shell/canvas context-menu path.
- `REQ-UI-022`: the active `media.panel` node shall render image, PDF, or video mode from one effective `source`. When the input is exposed, exactly one connected Path, String, or Image value is authoritative; Browse, Inspector editing, repair, internalize, crop replacement, and trim replacement shall be disabled, and the authored source shall never be used as fallback. Waiting, running, empty, failed, blocked, stale, invalid, and unsupported input shall clear the previous renderer and show an explicit message. Source and mode changes shall preserve node geometry and dormant mode settings, while inline and fullscreen views shall share the same effective-source resolution and release the previous renderer on transition. Mail shall remain a separate passive node.
- `REQ-UI-023`: interactive graph surfaces shall follow the locked, planned-public host/surface input contract: node-body interactions stay under the loaded surface, ordinary controls publish `embeddedInteractiveRects`, whole-surface modal tools use `blocksHostInteraction`, reusable controls come from `ea_node_editor/ui_qml/components/graph/surface_controls/` without reopening the public `graphNodeCard` / `graphCanvas` contract, and scope-capable shells expose subnode entry through the hover-reveal floating toolbar and context-menu paths while title double-click stays reserved for the shared header title editor.
- `REQ-UI-025`: passive flowchart surfaces shall render four exposed handles keyed `top`, `right`, `bottom`, and `left`, keep raw port labels hidden on flowchart host/drop-preview surfaces, anchor those handles on the exact silhouette perimeter, publish `origin_side` plus gesture-ordered source/target authoring when a connect gesture starts from a neutral flowchart port, and expose timestamp-only surface toolbar actions for live display, snapshot-to-now, and calendar-style manual date/time entry.
- `REQ-UI-026`: `Group` shall render as the dedicated `passive.annotation.group_backdrop` passive grouping surface under `Utilities > Canvas`, on a canvas layer below edges and regular nodes. It shall stay distinct from connectable annotation cards, have no Group shadow, and support library/drop placement plus wrap-selection creation through shortcut `C` without changing `Ctrl+Alt+G` / `Ctrl+Shift+G` structural grouping shortcuts.
- `REQ-UI-027`: Group shall reuse the shared header inline title editor with an empty default title. An untitled Group shall show `Double click to edit title` only when selected, and double-clicking that header shall start title editing. Group shall expose no body/rich-text content or Inspector-editable properties while collapsed descendants remain hidden on the canvas and expanded-versus-collapsed clipboard/delete affordances stay predictable to the user.
- `REQ-UI-028`: save/open/recover project-file UX shall stay lightweight: warnings and prompts summarize temporary and broken entries, and a compact `Project Files...` dialog shall list saved files, temporary files, and broken file entries without introducing a full artifact-manager pane.
- `REQ-UI-029`: Save As shall create one self-contained new `.cxproj` plus sibling `.data` tree, carry currently referenced saved files and referenced temporary files into destination-managed storage, and refuse to replace an existing destination project or sidecar. It shall not present a project-file-only or copy-mode choice. The live project path and runtime binding shall change only after the committed destination is reopened, verified, and adopted.
- `REQ-UI-030`: source-import workflows shall honor an app preference for `managed_copy` versus `external_link`, defaulting to managed copy, and tracked missing-file surfaces shall stay limited to the packet-owned node-level repair affordances for passive media, File Read, and Excel Read.
- `REQ-UI-031`: `Process Run` shall expose an inline `Output Mode` quick control limited to `memory` and `stored`, with a status chip that explains whether stdout/stderr stay inline or emit temporary transcript refs.
- `REQ-UI-032`: the cross-process viewer UX shall ship `model.viewer` as a viewer-family surface whose QML-shell-client state flows through `viewerSessionBridge` projection into `ViewerHostService`, preserves reopen summary plus `backend_id` / `transport_revision` metadata, surfaces explicit `rerun_required` blocker messaging when live transport is unavailable, starts in proxy mode without native warm-up, and permits one inline live viewer only after explicit proxy-viewport activation. Selection, hover, and single-click shall not activate it; selection or background loss shall demote it; fullscreen and detached presentation holds shall remain explicit; and hidden retention shall be limited to a widget previously activated inline.
- `REQ-UI-033`: Graphics Settings shall expose one canvas-global `Crossing style` control backed by `graphics.canvas.edge_crossing_style`, limited to `none` and `gap_break`, defaulting to `none`, and keeping the choice global-only without per-edge overrides or `.cxproj` persistence-payload expansion.
- `REQ-UI-034`: Active-node chrome shall retain run-scoped progress, completion, failure, elapsed-time, and error inspection while using fixed light/dark semantic colors. Failed nodes shall use the red/pink body fill with the existing error badge, and warning nodes shall use the yellow body fill with the existing warning badge; default, running, completed, and fresh-run nodes shall use the neutral body, with running retaining only its existing non-glow progress/elapsed presentation. Selected active nodes shall use the fixed blue selected fill and outline without a halo, and every execution halo, pulse, flash, or glow shall be absent. Passive styling and passive selection glows shall remain unchanged. A fixed disabled palette shall be available for future use but shall not create a disabled-node state or behavior. Required waiting inputs without a declared property default shall be yellow; inactive/no-data outputs gray; successful outputs filled green; and unwired property-default inputs outlined green. Ordinary data wires shall never turn red for runtime failure: red grips or wires mean invalid type only. These facts remain session-only and shall not add project persistence or a second execution-state channel.
- `REQ-UI-035`: Graphics Settings shall expose one app-global `Theme > Typography` control backed by `graphics.typography.graph_label_pixel_size`, defaulting to `10` and clamping to `8..50`, and graph chrome shall derive the shared `GraphSharedTypography` role hierarchy plus centralized weights from that one base size: standard node title `base + 2`, port labels `base`, elapsed footer `base`, inline property labels `base`, badge text `max(9, base - 1)`, flow edge label text `base + 1`, and flow edge pill text `base + 2`; existing passive `visual_style.font_size` and `visual_style.font_weight` paths remain authoritative where already wired, and the feature shall not add a graph-theme typography schema, per-node typography overrides, or `.cxproj` persistence-payload expansion.

When no enabled incoming wire overrides it, the input shall render as an outlined-green default grip. The row shall reuse the declared property editor metadata and existing property commit path for supported slider, toggle, text/number, enum, path, color, and textarea editors; blank or unsupported editor metadata shall render the grip without inventing a new widget. A connected input shall keep the embedded editor visible but muted and disabled, display a safe upstream value when available or the neutral placeholder when it is not, never delete or rewrite its saved authored property, and restore that authored value immediately on disconnect. Default-bound properties shall remain inspector-editable but shall not appear as duplicate canvas body/group rows.
- `REQ-UI-037`: graph canvas shall retain the per-view `hide_optional_ports` decluttering control and its view-local persistence so one view may hide unused optional rows while another keeps them visible; connected optional rows shall remain visible. The retired active-node `hide_locked_ports` control, padlocks, row tint, forbidden cursor, manual lock toggle, and empty-canvas lock gestures shall be absent, while unavailable add-on placeholder locks and passive-object locking remain unchanged.
- `REQ-UI-038`: graph canvas node headers shall render a leading local title icon only for `active` and `compile_only` nodes when the derived live `icon_source` resolves to a supported local `.svg`, `.png`, `.jpg`, or `.jpeg` file; passive nodes remain iconless in the title row even when authored `icon` metadata exists, the collapsed Group glyph stays on the existing `uiIcons` / `comment.svg` path outside this image-path contract, repo-managed SVG title icons track the active header text color through derived `icon_theme_aware` rendering, raster plus plugin/add-on image colors remain authored/untinted by default, and Graphics Settings `Theme > Typography` shall expose a nullable app-global `graph_node_icon_pixel_size_override` automatic/custom control whose `null` mode follows `graph_label_pixel_size` and whose explicit values clamp to `8..50`.
- `REQ-UI-039`: overflowing `VIEWS` and `WORKSPACES` tab strips shall keep the create action visible, show left/right overflow controls only when needed, auto-reveal the active tab after switch/create/reorder refreshes, and support hovered native-horizontal or `Shift+wheel` scrolling without changing graph-canvas wheel behavior.
- `REQ-UI-040`: eligible passive image media, passive PDF media, and supported viewer nodes shall expose shell-owned content fullscreen through `contentFullscreenBridge`, surface buttons, and the graph-canvas `F11` shortcut; the fullscreen surface shall remain a transient in-app overlay with one active node at a time, close through `Esc`, `F11`, and the close button, preserve image crop/page/fit preview semantics without editing node properties, block background graph interaction while open, and avoid `.cxproj` persistence expansion.
- `REQ-UI-041`: shell shall expose `Add-On Manager` as a top-level menubar entry that opens the Variant 4 inspector-style right drawer, preserves requested `focus_addon_id` selection across repeated open requests, renders catalog rows plus `About` / `Dependencies` / `Nodes` / `Changelog` detail tabs from the live add-on contract, and surfaces enable or disable plus restart-state messaging without widening into marketplace, update, or install workflows in this packet set.
- `REQ-UI-042`: missing add-on nodes shall remain visible on the canvas as locked Mockup B placeholders with a `LOCKED` badge, add-on requirement ribbon, lighter `Load...` affordance, aggregate `Load missing add-ons` canvas banner, and blocked title, property, drag, and resize mutations while the corresponding add-on is unavailable.
- `REQ-UI-043`: graph canvas and shell UX shall expose `io.folder_explorer` as a passive Classic Explorer surface discoverable from `Input / Output`, with inspector folder browsing, breadcrumb navigation, details rows, search/sort controls, context-menu commands, drag-out Path Pointer creation, and transient surface state that does not expand `.cxproj` persistence.

- `REQ-UI-047`: shell Help UX shall expose a `Keyboard and Mouse Reference` dialog from the menubar that lists current user-facing keyboard shortcuts, mouse gestures, optional-port decluttering and Ctrl-drag wire gestures, context-menu gestures, and focused editor controls across the shell, graph canvas, graph surfaces, overlays, media/fullscreen surfaces, library, inspector, and tab strips, with autocomplete Context and Action filters for lookup.

## Run Control UX
- `REQ-UI-059`: The shell run toolbar shall expose Run, Run Selected, Stop, and workspace-local Auto/Manual-Pause controls, with no Run Upstream Chain action. Auto shall be the app-default mode, evaluate immediately when a project opens, and reflect the live workspace mode; changing Manual/Pause shall not rewrite the app preference or `.cxproj`. `core.trigger` shall expose its compact click control, while If shall use ordinary data authoring. Stream Gate shall use the shared `REQ-UI-062` dynamic-port-group controls for its stable outputs. Explicit Run and Run Selected shall pass through the `REQ-UI-013` pending-Apply synchronization before dispatch.
- `REQ-UI-060`: Every edge shall expose checked Enable state in its context menu and selected-edge toolbar plus Ctrl+E. Disabled edges shall remain selectable and hittable but contribute no dependency or value. Only standard data wires incident to an `active` or `compile_only` node shall use the active-data presentation: Item is one solid stroke, List one round-dotted stroke, Tree one rounded-dashed stroke, and Empty two fine parallel hairlines with hollow endpoints. Patterns stay screen-space stable. `visual_style.display_mode` shall normalize to checked Default, Faint, or Hidden controls without changing runtime behavior: Faint keeps logical hit geometry and bounded tooltip access; Hidden shows only endpoint arcs, does not intercept body clicks, and reveals its full blue route while selected or marquee-selected. Direct selection is blue while preserving structure; selected active-node incident wires use a node-centred blue fade; invalid compatibility retains the destination red grip and input-centred red gradient. Disabled active data wires retain their structure with a centred X; Faint fades it and Hidden omits it. Passive-only and passive `flow` edges retain their existing rendering and interaction. Hover tooltips shall derive only bounded summaries from the existing output cache: Item safe text, List count plus the first eight indexed values, and Tree branch/item counts plus the first eight paths and first eight items per shown path, with each sample limited to 160 characters and explicit never-run, empty, stale, and current states. Full runtime values shall never enter QML payloads, no second cache shall be created, and ordinary wire rendering shall not represent runtime progress or failure.
- `REQ-UI-061`: Declarative inline/default properties shall flow through the shared presentation and QML path, not node-local controls: `value` remains the authored persisted value, while `display_value`, `display_value_available`, `overridden_by_input`, `condition_enabled`, and `editor_enabled` describe safe upstream display and editability. The canvas and Inspector shall reuse scalar slider, `interval_slider`, normal enum, searchable enum, text, and toggle controls. Wired and condition-disabled rows remain visible and retain their grips/topology; they are disabled rather than hidden. New settings groups begin collapsed and later expansion persists through the existing group state.
- `REQ-UI-062`: The graph canvas shall expose one shared dynamic-port-group authoring surface for node groups that declare insert, remove, or rename capabilities under `REQ-NODE-046`. The existing port layer and generic graph actions shall dispatch only graph-owned `REQ-GRAPH-021` commands, never write backing properties directly, keep controls separate from port hit targets, and provide keyboard, tooltip, and accessibility affordances. Stream Gate shall adopt this surface; node-local controls, user-editable `PortSpec` or group metadata, and a standalone reorder action shall not be added.
- `REQ-UI-063`: `PropertySpec` shall mark a property as sensitive and optionally name its protection-scope property. Shared canvas and Inspector projection shall replace every sensitive authored value with only `{has_value, scope}` and render the same masked Replace/Clear editor through dedicated secret mutation commands. Generic property setters shall reject sensitive writes, plaintext shall be protected before graph mutation or undo capture, scope changes shall atomically re-protect any stored value, malformed stored envelopes shall remain redacted and clearable, and neither plaintext nor ciphertext shall enter QML payloads.
- `REQ-UI-064`: Decorator-defined Python Script inputs, properties, paired `port=True` overrides, and settings groups shall project through the existing resolved-spec presentation payload and shared QML controls. Apply diagnostics shall retain source line and column information; invalid drafts shall remain dirty without changing the applied node. The default source shall include commented templates for every supported decorator, and the fullscreen shared editor shall expose a Guide toggle for a selectable, scrollable, theme-aware rich-HTML reference. Python Script shall not add a node-specific QML control renderer or a second editor path.

- `REQ-UI-057`: The shell shall provide planned solver-neutral FEA authoring and monitoring UX for composing process stages, assigning typed connections, units, coordinate systems, and scoping, validating missing or unsupported solver capabilities before dispatch, and inspecting stage status, neutral artifacts, and solver-specific diagnostics without making the existing neutral viewer contract solver-authoring-aware. Evidence crosswalk: `SYN-OPP-0008`.
