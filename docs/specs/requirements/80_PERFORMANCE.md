# Performance Requirements

## Targets
- `REQ-PERF-001`: Target scale is `1000` nodes / `5000` edges per scene. Published benchmark evidence shall record the exact synthetic graph size used for each run.
- `REQ-PERF-002`: Pan/zoom p95 frame time target is `<= 33 ms` on reference hardware when measured through the actual `ea_node_editor/ui_qml/components/GraphCanvas.qml` render path.
- `REQ-PERF-003`: Project load target is `< 3s` for a target-scale graph. Published load timings shall state whether they measure serializer/model/bridge setup only or a fully rendered frame.

## Rendering Strategy
- `REQ-PERF-004`: Viewport interaction work shall stay on the `ViewportBridge` / `GraphCanvas.qml` path and avoid duplicate pan/zoom invalidation scheduling.
- `REQ-PERF-005`: Edge, label, and background work shall stay viewport-aware and avoid full-scene processing when offscreen content cannot contribute to the visible frame.

## Concurrency
- `REQ-PERF-007`: Heavy execution/analysis work shall run outside the UI thread.
- `REQ-PERF-009`: When `graphics.canvas.edge_crossing_style` resolves to `gap_break`, crossing decoration shall stay render-only, compute gap sizing in screen space, and keep previewed and selected edges above ordinary edges with remaining ties resolved by visible-edge order.
- `REQ-PERF-010`: Dataflow presentation shall reuse the existing edge geometry, spatial index, centerline hit target, viewport culling, output cache, and execution-state revision paths. Item/List/Tree multi-stroke rendering shall not multiply hit geometry; disabled and empty edges remain hittable; cache-derived previews shall inspect at most eight list items, eight tree paths, and eight items per shown path with 160-character samples; and QML shall receive only bounded summaries rather than full runtime values or a second cache.
- `REQ-PERF-011`: shared graph typography shall keep deterministic metric alignment between the normalized `graph_label_pixel_size` preference, `GraphSharedTypography` role sizes, graph scene payloads, and geometry/width estimation: `standard_metrics.py` and the payload-width math shall consume the same clamped base value, shared typography updates shall reuse the existing graph-canvas payload refresh or revision seam, and the feature shall not introduce a second typography-only invalidation channel or stale clipping/label-width drift at non-default sizes.
- `REQ-PERF-012`: property-default grips, embedded editors, optional-row filtering, and Ctrl-drag endpoint reassignment shall stay on the existing graph-scene payload, host-row, property commit, canvas-input, validated-mutation, and history seams. Active-view optional filtering shall filter emitted rows instead of rebuilding graph topology; default editors shall reuse existing row controls; Ctrl-drag shall reuse existing socket/edge hit geometry; and the feature shall not introduce a second default store, property bridge, view-filter invalidation path, wire model, or history framework.
- `REQ-PERF-013`: node-title icon presentation shall stay on the existing graph-scene payload, shared header, and shared typography seams: header rendering consumes only the already-derived local `icon_source`, derived `icon_theme_aware`, active `headerTextColor`, and the effective node-title icon size, preserves centered/elided title reserve math and the collapsed group exception for `Group` on the existing header path, allows repo-managed SVG title icons to theme-tint from the header text color, keeps raster plus plugin/add-on image colors authored/untinted by default, and shall not add remote image loading, a second icon-specific invalidation path, or layout drift outside the shared header refresh path.

## Closeout Evidence Governance

- `REQ-PERF-014`: retained internal performance closeout evidence shall distinguish absolute target passes from comparable relative gains, product/internal gates from formal display-attached acceptance, and supplemental diagnostics from binding metrics. Missing baseline phases shall remain `UNVERIFIED`; process-wall improvement shall not be substituted for a regressed shell-create phase; display-attached `qquickwidget` / Direct3D 11 evidence with no software fallback and zero-loss parity remains authoritative for the staged display gate.
- `REQ-PERF-015`: Model Viewer V1 shall render composite datasets in one reusable PyVista/VTK widget, retain camera and actor/dataset state across same-revision display changes, release scene state on close/reset, and keep the release performance targets explicit: interaction frame p95 `<=33 ms`, full-detail restoration within `500 ms`, warm-cache coarse live frame within `5 s`, and no UI-thread loading interval above `100 ms`; only display-attached Windows/D3D11 evidence may close those targets.
- `REQ-PERF-016`: The dataflow cutover shall schedule each node once per requested solution, keep all Item/List matching calls within a node sequential, and aggregate outputs privately before one publication. It shall not add parallel node execution, durable solution snapshots, a generic tree editor or utility-node family, dynamic access overrides, remote execution protocol, additional event-source nodes, persisted runtime DataTrees, or unbounded preview traversal.
