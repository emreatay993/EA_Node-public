## Common Changes
- `GraphCanvasBackground.qml` binds grid coordinates to the live viewport. `GraphCanvasGridShader.qml` and `shaders/grid.frag` draw both styles in one GPU quad with physical-pixel coverage; no per-dot delegates or zoom-bucket geometry cache. Point marks are 1.25/2 logical pixels with stronger contrast against the canvas fill; only the shader input converts these sizes to physical pixels. Software rendering (or shader errors) uses the existing single Canvas painter. `tests/test_graph_canvas_grid.py` checks live alignment, constant scene size, visibility and rendered pixels; run it with `python -m unittest tests.test_graph_canvas_grid` on Windows/D3D11 as well as software.
- Rebuild the committed grid shader with `scripts/build_canvas_grid_shader.ps1 -Qsb <Qt-bin/qsb.exe>`. The source and `.qsb` live under `ea_node_editor/ui_qml/components/graph_canvas/shaders/`; wheels and frozen packages ship the `.qsb` so runtime needs no compiler.
- Keep canvas state projection and command bridge changes paired.
- Keep `GraphCanvas.qml` composed directly from `GraphCanvasStateBridge`, `GraphCanvasCommandBridge`, and `_canvasViewportBridge`; do not add an aggregate canvas facade, adapter, alias, or fallback.
- `GraphCanvasStateBridge` and `GraphCanvasCommandBridge` receive exact domain owners and no aggregate canvas/shell fallback. State splits session state/signal/size, app preferences, persisted graphics, execution/project, scene, and viewport. Command splits run, scope/hint, Inspector, Library, edit/drop, media, graphics, host, scene, viewport, and navigation/model routes.
- Route gesture/input behavior through canvas input layers and node host gesture layers.
- Manual node resize handles and hit zones are owned by `GraphNodeResizeHandle.qml` and are available only when `runtime_behavior` is `passive`; active and `compile_only` nodes still accept automatic and programmatic geometry updates. On eligible passive nodes, double-clicking either right corner requests expand-only fit-to-displayed-text through `GraphNodeHost.qml` and the loaded inline-properties layer, then persists through the existing `resizeFinished` geometry path; releases without geometry movement must not commit history.
- Scope-capable subnode entry is exposed by node body double-click, node context menu, and the hover-reveal floating node toolbar; the shared header title remains reserved for inline title editing.
- Empty-canvas options are opened from the top-right gear and empty-canvas right-click path; keep `GraphCanvasOptionsMenu.qml`, `GraphCanvasContextMenus.qml`, and bridge command/state projection updates in sync. Right-click opened node, edge, selection, and empty-canvas context menus use scene anchors so they move with pan/zoom; the gear-opened options menu stays screen anchored. The gear can be hidden by the app-wide `graphics.canvas.show_canvas_options_button` preference without disabling the menu path.
- Number Slider settings and Timestamp use the app-theme `components/common/DialogSurface.qml`, `DialogTextField.qml`, and `DialogButton.qml` family rather than inheriting node visual-style colors. `GraphCanvasSurfaceEditorOverlays.qml` owns their overlay placement and outside-click cancellation together with Web Address, Select, and Panel; RootLayers retains live aliases and one dispatch delegation. Node Browser shares the same presentation family under its existing owner.
- The canvas has no execution/failure grips, retired execution-control Settings row, compact execution endpoints, authoring-mode selector, or control-edge animation. `GraphNodeSettingsGroupsLayer.qml` renders only spec-declared named input groups in a shared host-owned bottom band across standard/viewer/plot/custom bodies. Collapsed group sockets are display-only; real child data ports and wires remain explicit and become authorable again only when expanded. Unrelated passive `flow` ports retain their existing presentation.
- Normal data-wire drop previews replacement of every existing wire at the target input; the new candidate stays solid while replaced active-data wires become faint/dotted. Shift previews ordered fan-in append with a positive marker. When the existing `wireDragState` becomes active, `GraphCanvasInteractionState.qml` loads one Python-owned fingerprinted compatibility snapshot for the real gesture and reuses it for moves and release. The snapshot resolves current effective ports, target accepted unions, conversions, and runtime-check compatibility; malformed snapshots, role errors, or catalog-generation mismatches fail closed. `GraphCanvasCommandBridge.request_rewire_edges(...)` moves the complete Ctrl-drag incident bundle atomically; Ctrl+Shift copies only the sole or explicitly selected edge and leaves its original. Blank release disconnects the moved bundle without Quick Insert, and cancel/original/incompatible release is a no-op. Graph-owned commit revalidation and passive `flow` capacity rules remain unchanged.
- Inputs with an explicit `default_property` payload render an outlined-green grip and reuse the existing property controls/commit bridge. Enabled incoming wires keep the editor visible but muted and disabled, display a safe upstream value or neutral unavailable placeholder, and never clear the authored property; disconnect restores that authored display. Keep editor rectangles in the shared input-blocking registry so canvas dragging does not steal control interaction.
- Shared active-node controls use the declared presentation facts rather than local connection logic: `value` stays authored, supported upstream `display_value` is muted and non-editable, unavailable display values use the neutral disabled placeholder, and `editor_enabled` also reflects `PropertyConditionSpec`. Condition-disabled rows remain in place with their grips and wires. Named settings groups start collapsed and only their persisted `expanded_settings_group_ids` state changes after the user opens them.
- Sensitive controls reuse `components/common/SecretEditor.qml` and publish only redacted state. Replace/Clear signals route to dedicated graph-scene secret commands; never prefill or send an envelope through generic inline-property commits.
- `GraphNodePortContextMenu.qml` directly owns the standard data-port root Menu and shows read-only Item/List/Tree access plus checked Graft, Flatten, Simplify, Reverse, Clean, eligible Principal, and dynamic insert/rename/remove actions. It calls the existing `GraphNodePortsLayer.qml` mutation/context methods through an explicit owner; the layer retains placement/opening and Principal still clears any sibling selection. Edge context/floating-toolbar actions and Ctrl+E toggle the durable enabled state. Active-data edge menus expose Default/Faint/Hidden; the canvas options menu applies the same display mode atomically to selected active-data wires, while passive-only and `flow` edges remain unchanged.
- `GraphActionPresentation.js` is the sole stateless QML owner for presentation-only action lookup, edge path/display normalization, field shaping, menu/popover extraction, and stable ordering/grouping/filtering across canvas context/options menus, edge/node toolbars, the extracted node-popover host, and `GraphNodeHost.availableActions`. It receives resolved DTOs/facts only, adds no QML object or frame dependency, and never decides mutation, media/fullscreen/viewer/plot policy. `GraphCanvasActionRouter.qml` remains the sole dispatch owner.
- `GraphNodeToolbarPopoverHost.qml` directly replaces the old inline action-popover bridge Item and owns action-popover state, placement/focus/hover, draft flush, and source-storage/bookmark/font-size/PDF/font-family panels. `GraphNodeFloatingToolbar.qml` retains toolbar anchor/chrome/grace, primary buttons, run menu, live aliases and public delegation; their combined Item/Binding/Repeater counts remain unchanged.
- Renderer-neutral edge paint facts live in pure `EdgePaintPolicy.js`; `EdgeMath.js` owns shared anchors. Canvas retains tracing/crossing/label-break paint, retained QML retains model/Shape delegates, and the unsupported native-scenegraph placeholder retains its exact Canvas fallback. Do not restore a retained-to-Canvas method dependency.
- `core.trigger` renders as a compact pill (`passive/GraphTriggerSurface.qml`) whose centered `GraphSurfaceButton` follows the node rename (fallback "Trigger"). The button click emits `triggerNodeRequested` and routes to the RunController capture/publication path; the node stays iconless with no execution grip or title icon, and its elapsed-time badge is suppressed like the other Data/Control pills.
- Multi-selection envelopes render from `GraphSelectionEnvelopeOverlay.qml` in `GraphCanvasRootLayers.qml` between node hosts and existing floating toolbars. Node floating toolbars open only for a singleton selection by default; the app-wide hover opt-in may reveal one on hover. Compute selection bounds from visible node/backdrop hosts where possible so live drag/resize geometry stays in sync; keep edge-only selection owned by `GraphEdgeFloatingToolbar.qml`. Plain edge click selects one wire, Shift-click toggles additive selection, held-W marquee selects routes live, and Ctrl+Left/Ctrl+Right jump an exactly-one selected wire to its source/target without changing zoom.
- Active and `compile_only` body gradients, outlines, title/port/inline-control foregrounds, warning/error fills, and blue selected fill resolve from fixed shell-brightness colors in `GraphNodeHostTheme.qml`; custom graph-theme node tokens and per-instance `visual_style` do not affect them. Active selection has no glow, and `GraphNodeChromeBackground.qml` contains no execution/preview/selection halos, pulses, or flashes. Passive body gradients and selected outline/glow remain graph-theme-owned; idle passive outlines may still use `visual_style.border_color`, rectangular passive selection glow stays in `GraphNodeChromeBackground.qml`, and flowchart passive selection glow remains shape-aware in `GraphFlowchartNodeSurface.qml`.
- Standard-node port dots render grip flow states through `ea_node_editor/ui/support/port_flow_state.py` and only the output cache record named by a current `NodeSolutionFact`: successful non-empty values use filled green output grips, authored defaults use outlined green input grips, unresolved required inputs use yellow, empty/inactive/never-run/expired outputs use gray, and red means invalid type only. Disabled edges contribute no value; execution failure does not make ordinary data grips or wires red. Colors come from `GraphPortStateTokens`, and hollow grips use opaque `surfaceColor` interiors. `GraphNodePortRow.qml` directly owns the shared input/output row geometry, notch/dot/ring, gestures, dynamic remove, label/edit, tooltip/accessibility, flow/compatibility state, padlock painter, and interactive rectangles. `GraphNodePortsLayer.qml` retains both models/Repeaters, dynamic scheduling, notch cache/source, aggregate rectangles, context state/menu, add-button repeater, plus only the input slash/padlock/default child and output inactive-tooltip/padlock-Loader child. Dynamic add/remove handles are centered on the 9 px notch corner, render at 6 px resting and 14 px active, and reveal from the owning port/notch hover; their hit regions overlap the owning port hover region by 2 px so pointer handoff does not dismiss the action. An empty group follows any remaining port hover, while a fully portless node uses node hover so the first port remains recoverable. Remove tooltips identify only the input/output direction. Standard/passive grips anchor centered on the card edge (`port_dot_radius` 5.0, `standard_port_gutter` 11.5); rest diameter is 10 and interactive grips grow slightly on hover while retaining drag-compatible halos. With default-on `graphics.canvas.notched_ports`, `GraphNodeHostLayout.qml` owns eligibility/cache state and the shared row renders mirrored SVG half-disc notches at 9 x 18 logical pixels, using one fixed 54 x 108 cached raster per style for sharp zoom/HiDPI rendering without zoom-driven image reloads; settings-group aggregate notches share the same raster size. Collapsed, chrome-free passive/comment, and flowchart/cardinal-handle branches retain their existing rendering.
- Compatible targets reuse the existing port dots/rings, `ManagedToolTip`, and accessibility fields: the ring grows from 12 to 18 px as a non-color cue, while waiting and invalid/error outlines keep precedence over the type-family accent. `GraphThemeBridge.resolve_data_type_color(...)` currently maps projected family tokens to the active theme's existing data-port color and updates reactively on theme changes. T08 adds no QML type registry or renderer, no per-port catalog/assignability payload, and no new per-port edge scan; the pre-existing duplicate/capacity edge scan remains.
- `GraphNodeHeaderLayer.qml` and `GraphNodePortRow.qml` reuse schema help through General-category managed tooltips, with `GraphNodePortsLayer.qml` supplying the bridge and retained output-only inactive tooltip. Node help is name/category/description/keywords; port help is label, direction/type/access, description, and a bounded cache-derived preview that distinguishes never-run, empty, stale, and current without placing full runtime values in QML payloads. `GraphNodeHeaderLayer.qml` also owns the Warning-category diagnostic badge; missing required `waiting` inputs or retained runtime warnings produce the fixed yellow active body, failures produce the fixed red/pink body, selected active blue fill outranks both while retaining the badge, and ready-but-unrun/running/completed/fresh nodes use the neutral body.
- The pixel-review gallery for node chrome, grip states, and inline controls is `python -m ea_node_editor.mockups.node_restyle` (`--theme dark|light|both`, `--screenshot-dir`); it injects the real fixed active palettes plus passive graph-theme tokens and instantiates the real surface controls. Active glows are forbidden; passive selection glows still need an interactive compositing check.
- Node-link hover badges and preview cards live in `GraphNodeLinkHoverLayer.qml` under `GraphCanvasRootLayers.qml`; keep them theme-aware, zoom-positioned from node hosts, routed through the canvas command bridge, and cleared or resynced when scene nodes, scope, or workspace state changes.
- Node comment Count Pill badges and the canvas comment popover live in `GraphNodeCommentPopoverLayer.qml` under `GraphCanvasRootLayers.qml`; keep Concept A geometry/tokens, the bottom-right resize grip clearance, and the `graphics.canvas.node_comment_editor_default` route through `GraphCanvasOptionsMenu.qml`, `GraphCanvasPreferenceFacts.qml`, and graph-canvas command/state bridges.
- Empty-canvas input/drop catchers (`GraphCanvasInputLayers.qml`, `GraphCanvas.qml`'s OS path drop layer) must stay behind node content and must not block node/port hover. Comment ghost-badge hover must not use a full-node overlay above ports; rely on host hover for empty-node ghost visibility.
- Existing Path Pointer nodes own a whole-host `DropArea` in `GraphNodeHost.qml`. A single OS or Native Explorer path routes through `GraphCanvas.performPathPointerNodeDrop(...)` and the canvas command bridge's bulk `path`/`mode` update; multi-item and locked/read-only drops use `Qt.IgnoreAction` so they cannot fall through to empty-canvas node creation. Empty-canvas mail/file/folder drop behavior remains owned by `GraphCanvas.qml`.
- `GraphCanvasRootLayers.qml` receives `themePalette` from `GraphCanvas.qml`; overlay text should resolve shell colors from that palette before using legacy/global fallbacks.
- Canvas view export captures only the base canvas stack through `GraphCanvas.exportCanvasBasePng(...)`; plain `CanvasExportPresenter` owns exact visible-model preparation, framing, saved-viewport application, live/model restore, overlay composition, crop extents, ordering/naming, and PNG/PPTX output. Keep transient toolbars, selection overlays, hover cards, minimap, and shell overlays outside that base grab.
- For performance changes, use the performance harness route and focused graph tests.
- Keep the two viewport rectangles distinct. `ViewportBridge.visible_scene_rect_payload` is the exact scene rectangle and drives `GraphNodeHost.inVisibleViewport`, which expensive surfaces use to suspend work. `ViewportBridge.node_render_activation_scene_rect_payload` is a buffered, bucketed look-ahead rectangle for host/surface retention only; it must not drive work suspension.
- Retention uses independent horizontal/vertical margins of half the viewport clamped to 240-640 screen pixels, plus 160 pixels of movement hysteresis and 128-pixel outward buckets. When the exact viewport's 128-pixel safety band reaches the retained edge, rapid view changes are coalesced to one visible-model publication per GUI frame; if the exact viewport escapes the current retained region, publication runs immediately so visible nodes never lose their hosts. `GraphCanvasRootLayers.qml` shrinks back to the steady margins after the existing idle delay.
- `tests/test_qml_drill_budget.py` ratchets property drilling through the pass-through hubs (`canvasItem.` in `GraphNodeHost.qml`, `rootBindings.` in `GraphCanvas.qml`). Do not add new drilled pass-throughs; route new canvas-level facts through the shared facts/interaction objects and ratchet the budget down when drilling is removed.
- Payload-cache mutation/sync (cached node/edge payload replacement, removal, rebuild, inline-title sync) is owned by `ea_node_editor/ui_qml/graph_scene/payload_cache_sync.py` (`ScenePayloadCacheSync`); `graph_scene/context.py` keeps publish_* orchestration (delta classification, signal emission) and delegates cache mutation to the collaborator. Investigate payload-cache staleness there first.
- QML-heavy questions should check `docs/qml_navigation_index.md`, `docs/qml_navigation_index.json`, and `docs/agent_route_index.md` before bounded source reads.

## 2026-07-11 Performance Ownership

- Multi-drag membership freezes once at gesture start; scalar live offsets flow through `GraphCanvasFrameScheduler.qml`, and visible node hosts contain no per-node `Timer`. Comment/link overlays consume sparse badge projections; the inert hover repeater is retired.
- Edge cache ownership remains in `graph_scene/state_support.py` and `payload_cache_sync.py`: stable payloads replace in place, and one canonical structural add/remove updates sorted arrays plus routing indexes incrementally. Bulk or invalid changes retain full fallback.

## 2026-07-14 Node Insertion Performance

- Visible additions that contain only new, in-query node payloads append through one `rowsInserted` transaction. Mixed replacement/removal, offscreen, duplicate, or reentrant cases retain the general visible-model sync and duplicate-resync safeguards.
- Selection notifications for insertion run after the new visible rows are published. Existing rows satisfy selection membership without another viewport query; missing offscreen selections and dirty/deferred models still force the general refresh, while deselected offscreen-only rows are removed incrementally.
- Validated pure additions extend endpoint/minimap caches and the retained QML edge payload overlay without an endpoint-model rebind. Structural removals and mixed or ambiguous deltas continue through the full refresh path.
